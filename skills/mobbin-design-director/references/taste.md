# Recommend, then calibrate

The agent owns analysis, quality, and routine execution. The owner contributes
product intent and consequential visual judgment. Respect an explicit request
for autonomy; do not turn this workflow into repeated permission seeking.

## When a visual checkpoint helps

Use one when a consequential unresolved choice changes composition, visual
language, emotional character, or several screens and owner feedback would
materially improve it. Skip it for settled designs, standard platform controls,
minor details, and changes already authorized within a direction.

Read existing taste evidence, but keep its context. A choice for a calm finance
screen is not a universal preference for every product. Do not record an agent
default as an owner choice, or use one observation as an immutable rule.

## Show the decision

1. State the one choice being made.
2. Show comparable options using the same real content at a useful device scale.
3. Recommend one with a concise reason and the meaningful tradeoff.
4. Ask one focused visual question if owner input is needed.

Use reference images when they communicate the choice; use cheap prototypes of
our own screen when content, type, density, or interactions determine the answer.
Native chrome needs a native prototype. Do not ask someone to judge it from an
HTML imitation. If native tools are absent, explain what a content prototype can
and cannot demonstrate and continue independent design work.

Pairwise comparison is useful for close alternatives. Avoid presenting several
unrelated decisions at once, abstract adjective surveys, token controls, or a
large gallery without a clear decision. Stop when the direction is sufficiently
clear; do not manufacture alternative rounds after an explicit choice.

Example: “I recommend A: the total and next action are easier to find. B gives the
illustration more personality but pushes the detail down. Does A lose too much
warmth?” The recommendation is visible; alternatives are argued fairly.

## Interpretation and follow-through

Identify which quality appears to drive the preference: density, hierarchy,
typography, imagery, rhythm, or interaction. Mark interpretation as tentative
unless confirmed. Carry that quality into the product's own system.

Record actual choices with date/context, compared options, result, and confidence
in `design-taste.md`. Existing one-off/emerging/established labels remain usable;
repeated comparable choices strengthen confidence without making a numeric count
scientific evidence. Explicit owner instructions take precedence.

Implement routine details autonomously. Show the actual result after meaningful
visual work, stating any remaining consequential uncertainty. Do not require a
new approval if the user already authorized the work. Reopen a direction only
when new evidence exposes a material problem or the owner asks to change it.
