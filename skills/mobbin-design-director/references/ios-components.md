# iOS components: pick the native element

Read this when a job needs a control, a container, or a navigation element on iPhone and you want the HIG's pick before you draw.

This file gives the floor. Pick the native element for its behavior, then mold its appearance and feel to the product. See [ios-craft](ios-craft.md) for how Things, Copilot, Tide Guide and Family do that. A screen built only from this table is correct and stock, and stock is a tell in the [defaults detector](defaults-detector.md).

The live HIG is on iOS 27 (shipped September 2026, with iPhone Duo). iOS 26 introduced Liquid Glass. iOS 27 revised terminology, search tabs, menus, sidebars, scroll edge effects, and icons. Apple's doc says the `UIDesignRequiresCompatibility` opt-out is ignored when you build for iOS 27, so an app that still shows the iOS 18 chrome is an app built with an old SDK. Source: https://developer.apple.com/documentation/bundleresources/information-property-list/uidesignrequirescompatibility

Every URL below is under `https://developer.apple.com/design/human-interface-guidelines/`.

## Part A: task to component

| Task | Pick | Rule | HIG URL |
|---|---|---|---|
| Primary navigation on iPhone | Tab bar | Navigation only, never actions. Keep it visible except under a modal. Never hide or disable tabs. Avoid the More tab. Single word labels. Filled symbols. iOS 26 and later: floats at the bottom on Liquid Glass. May include a dedicated search tab at the trailing end. With an attached accessory (MiniPlayer) it may minimize on scroll, and it exits on tab tap or scroll to top. | https://developer.apple.com/design/human-interface-guidelines/tab-bars |
| Primary navigation with many sections (iPad) | Tab bar that adapts to a sidebar (`sidebarAdaptable`) | "Consider using a tab bar first." Default list of five or fewer tabs if customizable. Sidebar only means `NavigationSplitView`. | https://developer.apple.com/design/human-interface-guidelines/sidebars , https://developer.apple.com/design/human-interface-guidelines/tab-bars |
| Sidebar depth | Sidebar | Show no more than two levels. Deeper hierarchy needs a split view with a content list. Extend content beneath with the background extension effect. | https://developer.apple.com/design/human-interface-guidelines/sidebars |
| Show hierarchy side by side | Split view | Prefer regular width. iPad: two or three vertical panes. Persistently highlight the selection. | https://developer.apple.com/design/human-interface-guidelines/split-views |
| Hierarchical navigation | Navigation stack with the standard Back | Use the standard Back and Close symbols, no "Back" or "Close" text label. The large title shrinks to standard on scroll and returns at the top. Title under 15 characters. | https://developer.apple.com/design/human-interface-guidelines/toolbars |
| Scoped task that returns to its parent | Sheet | Detents: large (default) and medium (about half). Custom detents allowed. Include a grabber. Support swipe to dismiss. Confirm unsaved changes with an action sheet. One sheet at a time. Cancel leading, Done trailing. Never Cancel, Done and Back together. Done is always paired with Cancel or Back. | https://developer.apple.com/design/human-interface-guidelines/sheets |
| In depth or multistep task, media | Full screen modal | For videos, photos, camera, document or photo editing. | https://developer.apple.com/design/human-interface-guidelines/sheets , https://developer.apple.com/design/human-interface-guidelines/modality |
| Small transient info anchored to a control | Popover | Only in wide (regular) views. Use a sheet in compact. One at a time. Nothing over it except an alert. Never for warnings. | https://developer.apple.com/design/human-interface-guidelines/popovers |
| Critical interruption | Alert | Title plus optional text plus up to three buttons. Never purely informational or at launch. No alerts for common undoable deletes. Verb titles, "OK" only when informational. Cancel is never the default. Destructive style only for unintended destruction. | https://developer.apple.com/design/human-interface-guidelines/alerts |
| Choices that follow an intentional action | Action sheet (confirmation dialog) | Not an alert, not a menu. Destructive buttons on top, Cancel at the bottom. Avoid scrolling. | https://developer.apple.com/design/human-interface-guidelines/action-sheets |
| Commands revealed on demand | Menu or pull-down button | Verb labels, title case, no articles, ellipsis when more input is needed. Show unavailable items dimmed. Group with separators. Submenus one level, about five items at most. Pull-down: list at least three items. A destructive item triggers an action sheet (iOS). Icons: all or none within a group. iOS layouts: small (4 icon only), medium (3), large (list). | https://developer.apple.com/design/human-interface-guidelines/menus , https://developer.apple.com/design/human-interface-guidelines/pull-down-buttons |
| Secondary actions on an item | Context menu | Short. Hide unavailable items (do not dim). Destructive items last and marked. Items must also exist in the main UI. Never both a context menu and an edit menu on one item. | https://developer.apple.com/design/human-interface-guidelines/context-menus |
| Row actions by swipe | Swipe actions | The HIG only says: let people "swipe to ... initiate actions in a list row", and that the fill symbol variant suits swipe actions. No dedicated page. | https://developer.apple.com/design/human-interface-guidelines/designing-for-ios , https://developer.apple.com/design/human-interface-guidelines/sf-symbols |
| Actions on the current view | Toolbar | About three groups at most. One `.prominent` action (Done or Submit) on the trailing side. More menu only if needed. The system adds overflow on iPad and Mac. Prefer borderless symbols. No custom backgrounds, use the scroll edge effect. Custom components keep corner radii concentric with the bar. | https://developer.apple.com/design/human-interface-guidelines/toolbars |
| 2 to 5 views of the same content | Segmented control | Closely related subviews. About five segments at most on iPhone, five to seven when wide. Nouns. Text or images, not mixed. Separate app sections use a tab bar. | https://developer.apple.com/design/human-interface-guidelines/segmented-controls |
| On or off setting | Switch | Only in a list row. Outside a list use a button that behaves like a toggle. | https://developer.apple.com/design/human-interface-guidelines/toggles |
| Medium to long value lists, dates | Picker | Short lists: pull-down button. Very large: list or table. Date styles compact, inline, wheels. | https://developer.apple.com/design/human-interface-guidelines/pickers |
| Choose one from a short list | Pop-up button | "Mutually exclusive choices that aren't commands." | https://developer.apple.com/design/human-interface-guidelines/pull-down-buttons |
| Multi-select or reorder rows | List edit mode | iOS requires entering an edit mode before selecting rows. Info button only for detail, disclosure indicator for drill in. | https://developer.apple.com/design/human-interface-guidelines/lists-and-tables |
| Small text input | Text field | Placeholder plus a separate label. Secure field for passwords. Validate email on leaving the field, passwords before leaving. Clear button at the trailing end. Match the keyboard type (`keyboardType`, `textContentType`). Offer choices over typing. Never prepopulate a password. | https://developer.apple.com/design/human-interface-guidelines/text-fields , https://developer.apple.com/design/human-interface-guidelines/virtual-keyboards , https://developer.apple.com/design/human-interface-guidelines/entering-data |
| Search entry point | Search tab, toolbar search, or inline field | Tab styles: standard tab (landing page) or button appearance (keyboard immediately). Bottom toolbar if there is room. Top if content must stay visible. Inline when scoped to a view. Scope bar for defined categories, default broad. Tokens for common terms, paired with suggestions. | https://developer.apple.com/design/human-interface-guidelines/search-fields , https://developer.apple.com/design/human-interface-guidelines/searching |
| Progress | Determinate when possible. Spinner otherwise | Never switch circular to bar. Offer Cancel or Pause. Buttons can show an inline activity indicator. | https://developer.apple.com/design/human-interface-guidelines/progress-indicators , https://developer.apple.com/design/human-interface-guidelines/buttons |
| Status, success, warnings | Passive inline status. Alert only for critical. Confirm only significant tasks. Haptics through the standard feedback generators (notification, impact, selection) | | https://developer.apple.com/design/human-interface-guidelines/feedback , https://developer.apple.com/design/human-interface-guidelines/playing-haptics |
| New information in a section | Tab badge | Reserve for critical info. Notifications: never for errors (use an alert). | https://developer.apple.com/design/human-interface-guidelines/tab-bars , https://developer.apple.com/design/human-interface-guidelines/notifications |
| Lists vs grids | List for text. Collection for images or varied sizes | Grouped style uses headers and footers. | https://developer.apple.com/design/human-interface-guidelines/lists-and-tables , https://developer.apple.com/design/human-interface-guidelines/collections |
| Hide advanced options | Disclosure control | Most used on top. One disclosure button per view. | https://developer.apple.com/design/human-interface-guidelines/disclosure-controls |
| Empty state | Guidance plus a button | "Provide clear next steps on any blank screens." ContentUnavailableView is not named. | https://developer.apple.com/design/human-interface-guidelines/writing |
| Onboarding | Context specific tips (TipKit) over one flow | Tips: one or two sentences. Features of at most three actions. Frequency rules such as once per 24 hours. | https://developer.apple.com/design/human-interface-guidelines/onboarding , https://developer.apple.com/design/human-interface-guidelines/offering-help |
| Undo | System gestures (shake, three finger swipe). Buttons only when needed, in a toolbar | Describe the operation after "Undo " or "Redo ". | https://developer.apple.com/design/human-interface-guidelines/undo-and-redo |
| Settings | Task options in context. General options in in-app settings. Only rarely changed options in the Settings app, with a button that opens it | | https://developer.apple.com/design/human-interface-guidelines/settings |
| Sharing | Share button that opens the activity view | Never duplicate system actions. Custom icon about 70x70 px. | https://developer.apple.com/design/human-interface-guidelines/activity-views |

**Unconfirmed (not stated on any HIG page fetched):** the `.glass` and `.glassProminent` button style names, `TabViewBottomAccessoryPlacement` behavior details (the HIG links it, no text), a concentric corner radius API (the HIG only says "concentric with bar corners"), and `ContentUnavailableView`.

## Part B: numbers the HIG states

- Hit region: at least 44x44 pt (visionOS 60x60). Default and minimum control size on iOS: 44x44 and 28x28 pt. Padding about 12 pt around bezeled elements, 24 pt around unbezeled ones. https://developer.apple.com/design/human-interface-guidelines/buttons , https://developer.apple.com/design/human-interface-guidelines/accessibility
- Type: iOS default 17 pt, minimum 11 pt. Contrast 4.5:1 up to 17 pt, 3:1 at 18 pt or bold. Text enlarges by at least 200 percent. https://developer.apple.com/design/human-interface-guidelines/typography , https://developer.apple.com/design/human-interface-guidelines/accessibility
- Dynamic Type Large (the default): Large Title 34/41 Regular (Bold when emphasized), Title 1 28/34, Title 2 22/28, Title 3 20/25, Headline 17/22 Semibold, Body 17/22, Callout 16/21, Subhead 15/20, Footnote 13/18, Caption 1 12/16, Caption 2 11/13. Full xSmall to AX5 tables on the page. https://developer.apple.com/design/human-interface-guidelines/typography
- Margins and safe areas for iOS: the HIG states no number (tvOS: 60 pt top and bottom, 80 pt sides). https://developer.apple.com/design/human-interface-guidelines/layout
- SF Symbols: monochrome, hierarchical (depth), palette (two or more colors), multicolor (intrinsic). Nine weights, three scales. Outline for toolbars and lists, fill for tab bars and swipe actions. https://developer.apple.com/design/human-interface-guidelines/sf-symbols
- Color roles: label, secondary, tertiary, quaternary, placeholder, separator, opaqueSeparator, link. System versus grouped backgrounds (primary, secondary, tertiary). 12 system colors plus gray 1 to 6. Never hard code values. Liquid Glass has no inherent color. Tint only the primary action background. Keep toolbars monochrome over colorful content. https://developer.apple.com/design/human-interface-guidelines/color
- Materials: Liquid Glass (regular, clear, with an optional 35 percent dark dim over media) for the control layer only. Standard materials ultra thin, thin, regular, thick for content. https://developer.apple.com/design/human-interface-guidelines/materials
- Corners: "concentric with bar corners". Icons masked to match the device bezel curvature. https://developer.apple.com/design/human-interface-guidelines/toolbars , https://developer.apple.com/design/human-interface-guidelines/app-icons
- Motion: no durations given. Reduce Motion: tighten springs, track gestures, fades instead of x, y, or z transitions, no blur animation. https://developer.apple.com/design/human-interface-guidelines/motion , https://developer.apple.com/design/human-interface-guidelines/accessibility
- Dark Mode: no app level appearance setting. 4.5:1 minimum, 7:1 for custom colors. Base versus elevated backgrounds. https://developer.apple.com/design/human-interface-guidelines/dark-mode
- Writing: verb labels. Sentence case is more casual. Choose one style per element type. Alert titles title case if a fragment. No "we". Errors state the fix. Details in [ios-writing](ios-writing.md). https://developer.apple.com/design/human-interface-guidelines/writing
- App icons: 1024x1024 px square layers, unmasked. Icon Composer. Appearances default, dark, clear light and dark, tinted light and dark. Let the system add effects. https://developer.apple.com/design/human-interface-guidelines/app-icons

## Part D: every HIG component, by group

Part A is keyed by job, not by element. It is a decision aid, not a catalog, and
nothing outside it is banned. When a job needs an element Part A does not name,
pick it from this list and read its page with `scripts/hig.py <slug>`. Each page states its platforms. Some
entries are macOS or iPadOS only (Dock menus, Path controls, Column views, Combo
boxes, Image wells, Panels, Color wells), so check before using one on iPhone.
